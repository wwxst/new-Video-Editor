# Phase C — plan and first slice (2026-11-26)

**Branch:** `feat/phase-c-preview` (from `main` at `94f3c87`). **Plan:**
[docs/specs/phase-c-plan.md](../docs/specs/phase-c-plan.md). **Slice:** C1, the headless preview
frame pipeline in `arc_cli::preview`.

## 1. Plan summary

Phase C is the editor (docs/10 §5). The plan turns its deliverables into six ordered slices, each
with measurable acceptance criteria:

| Slice | Content | Key acceptance |
|---|---|---|
| **C1** | Preview frame pipeline (headless): decode + compose one frame at a timeline position, per-asset decoders, byte-bounded decoded-source cache | preview frame == export frame pixel for pixel; half quality; cache hits/no re-decode on repeats; warnings for unavailable/unsupported items; typed out-of-range |
| C2 | Preview scheduler + playhead (audio-clock placeholder, latest-wins, half quality while scrubbing, full when settled) | only the latest position renders; full-quality switch after quiescence; bounded queue; stub-pipeline tests |
| C3 | Editor shell and viewer texture (`arc-app`): docking, media bin, inspector, `PreviewEngine` frames as an `egui_wgpu` texture, GPU-side composited-frame cache (docs/03 §3) | app opens a project and shows the playhead frame; headless shell smoke test; IME manual check |
| C4 | Timeline canvas: paint, virtualization/LOD, hit testing, move/trim/split, snapping | pure hit-test/snap golden tests; one valid command batch per gesture; 100 clips at 60 fps |
| C5 | Titles/text renderer, LUT decision | titles render in preview and export; CJK fallback; golden image hash |
| C6 | Command palette, keymap, native dialogs | palette from the command registry; data-driven keymap tests |

Constraints: no new crates, no schema/protocol change; decode+compose stays in `arc-cli` (docs/01
§4: `arc-render` may not depend on FFmpeg, `arc-media` may not know the UI); GPU tests are serialized
per test binary because WARP crashes with concurrent devices (batch 3).

## 2. First slice (C1)

`crates/arc-cli/src/preview.rs` — `PreviewEngine`:

- `PreviewEngine::new(project, media_root, quality)` (or `with_renderer` to share the GUI device).
- `frame(n) -> PreviewFrame { frame, width, height, rgba, warnings }`: plans with the same
  `arc_render::plan::plan_frame` and composes with the same `Renderer` as the exporter.
- `PreviewQuality::{Full, Half}`: half renders the canvas at half size while decoders stay at native
  source resolution (verified by `cached_source_size`).
- One `VideoDecoder` per asset; an LRU of decoded **source** frames keyed by `(asset, source time)`
  because effects are applied after decode; bounded by **bytes** (default 256 MB) with a minimum of
  one entry, so a 4K frame cannot blow the budget. The docs/03 §3 GPU-side composited-frame cache
  (clip + effect-chain hash) belongs to C3, where the viewer owns textures.
- `set_project` keeps decoders only for unchanged asset paths and retries an asset whose path
  changed (relink/repair); the cache is cleared.
- Unavailable assets, titles and unimplemented effects become `warnings`; the frame still renders
  (background for the missing source), matching the exporter.
- `PreviewStats { frames, decodes, cache_hits }` for tests and scheduler diagnostics.

The exporter now shares `TITLE_WARNING` and `resolve` with the preview module so the two paths cannot
drift on those two contracts.

must-fix items were addressed before commit:

## 5. Risks and next steps

- **Preview rate is unmeasured.** The Phase C exit criterion (1080p ≥ 30 fps with 4 tracks and 8
  effects) needs the C2 scheduler and a benchmark on the reference machine; C1 only guarantees
  correctness. CPU decode + GPU upload per frame is the known cost (docs/03 §10).
- **No GPU-side composited cache yet** (C3). Until then a repeated edit re-composes from decoded
  sources; correctness is unaffected.
- **Half-quality scrub is not an exact downscale** for pixel-space effect radii (documented; C2).
- **Mid-stream decode failure fixture** (T3) is still missing; the malformed corpus in batch 2 and
  the import check cover the boundary, and the preview warns on open failure.
- Next slice: **C2 scheduler** (latest-wins, quality switch, injectable clock, stub pipeline), then
  C3 shell/viewer.
