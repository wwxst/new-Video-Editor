## 1. What was built

`crates/arc-cli/src/preview_scheduler.rs` — `PreviewScheduler`, the layer between the UI thread and
the C1 pipeline:

- **One worker thread** owns the `PreviewSource` (the real `PreviewEngine`, or a stub in tests).
  `request(frame)` is non-blocking and **latest-wins**: the pending slot is a single `Option`, so 200
  rapid positions cost one slot and at most two renders (in-flight + newest).
- **Generation-based cancellation.** Every request bumps a generation; when a render finishes, its
  result is stored only if its generation is still current. A newer request or `cancel()` therefore
  drops the stale frame instead of showing it, and `cancel()` also clears the pending slot and any
  stored result. The worker stays alive after a cancel.
- **Quality policy.** `PreviewPolicy { scrub_window, settle }`: a request within `scrub_window` of
  the previous one is a scrub → `Half`; a request from idle → `Full`; after a `Half` frame, if no new
  request arrives within `settle`, the worker re-renders that position at `Full` and marks the
  result `upgraded`.
- **Injectable clock** (`Clock` trait, `SystemClock`, a manual clock in tests) for the scrub window.
  The settle debounce uses real time like any UI debounce, and is covered with a short 40 ms policy.
- **Backpressure by construction:** pending request and result are O(1) slots; a slow render delays
  the newest frame only by the remainder of that render, and no queue can grow.
- `shutdown()` joins the worker; `Drop` does the same, bounded by one in-flight frame.

## 2. Tests (`crates/arc-cli/tests/preview_scheduler.rs`, 6)

| Test | Behaviour |
|---|---|
| `rapid_requests_render_only_the_latest` | blocked first render + 9 rapid positions → exactly 2 renders (in-flight and latest), delivered frame is the newest, quality is `Half` (scrub), older results dropped |
| `slow_render_does_not_block_the_newest` | while frame 1 is blocked, requests 2 and 3 arrive; after release the newest (3) is delivered in < 1 s, frames 1/2 never delivered |
| `settling_after_scrub_renders_full_quality` | jump from idle → `Full`; immediate next request → `Half`; after 40 ms quiescence the same position is delivered again as `Full` with `upgraded = true` |
| `cancel_drops_pending_and_in_flight_results` | cancel during an in-flight render → nothing delivered; the worker still serves the next request; generations increase |
| `backpressure_keeps_a_single_pending_request` | 200 requests while one render is blocked → 2 renders total, latest frame delivered |
| `shutdown_and_drop_leave_no_running_worker` | `shutdown()` joins and sets `worker_done`; dropping a scheduler with a pending request returns promptly |

No GPU is involved, so the tests are fast (~0.4 s) and run on the WARP-only CI runners too.

## 3. Supporting changes

- `crates/arc-cli/src/lib.rs`: registers `preview_scheduler` and sets
  `#![recursion_limit = "512"]` — moving a `Project` (deep `im` collections) into the worker
  overflows rustc's default obligation depth on the `Send` check; the limit only affects compile
  time.
- `crates/arc-cli/src/preview.rs`: `PreviewError` derives `Clone` so `PreviewResult` can be cloned
  by the consumer; no behaviour change.
- `PreviewEngine` implements `PreviewSource` by forwarding to `set_quality` + `frame`, so the GUI
  will hand its engine to `PreviewScheduler::new`.

## 5. Risks and next steps

- **Half-quality pixel-space effects** (blur/sharpen radii) are not scaled by the compositor, so a
  scrub frame is not an exact downscale of the full frame (carried over from C1; C4/C5 can scale the
  radii for the scrub path).
- **No GPU composited-frame cache yet** (C3): the settle upgrade re-composes from decoded sources.
- **The first frame of a drag renders at full quality** (a request from idle is `Full`); a later
  slice can pre-empt it with a half-quality first paint if the measured latency warrants it.
- **A slow render delays the newest frame by its remainder** (single worker, no pre-emption); if
  benchmarks show this matters, a second worker or cooperative cancellation inside the decoder is
  the follow-up.
- Next: **C3 editor shell/viewer** — `arc-app` uses `PreviewScheduler` behind an `egui_wgpu` texture,
  plus the docs/03 §3 GPU composited-frame cache.
