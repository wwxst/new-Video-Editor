# Phase C — slice C3: editor shell and viewer (2026-11-26)

**Branch:** `feat/phase-c-editor` (from `main` at `2280f23`). **Plan:** [docs/specs/phase-c-plan.md](../docs/specs/phase-c-plan.md).
**Previous:** C1 ([report](phase-c-c1-2026-11-26.md)) and C2 ([report](phase-c-c2-2026-11-26.md)).

## 1. What was built

- **Viewer + transport in the app**: `arcline --project <file>` opens the editor surface — the
  composed frame, Play/Pause, step back/forward, a timeline slider, a frame counter and timecode.
  Frames come from the C2 scheduler through the new C3 transport and are uploaded as an egui texture
  (`egui::Context::load_texture`, backed by egui-wgpu); the app never decodes or composes itself.
- **`PreviewTransport`** (`arc-cli`, GUI-free and testable): play/pause/seek/step, frame-accurate
  advancement from elapsed wall time at the sequence rate, latest-frame polling, and a
  **composited-frame cache** — full-quality frames are kept in an 8-entry LRU so scrubbing back over
  the same range displays instantly without re-composing.
- **App wiring**: `Options.project`, `Editor::open` loads the saved project (read-only snapshot),
  lazy pipeline attach on the first redraw (needs the GPU), a viewer/transport UI, and the existing
  PoC path untouched when `--project` is absent.
- **Benchmark data point** (see §2).

## 2. Benchmark — 1080p, 4 tracks, 8 effects

Test: `crates/arc-cli/tests/preview_benchmark.rs` (`preview_benchmark_1080p_4_tracks_8_effects`),
run standalone with `cargo test -p arc-cli --test preview_benchmark -- --nocapture`.

| Condition | Value |
|---|---|
| Adapter | `Intel(R) Graphics (Vulkan)` (reference machine, Intel iGPU) |
| Canvas | 1920×1080, 30 fps sequence |
| Timeline | 4 video tracks, one 1 s clip each (same 1080p FFV1 source), stacked |
| Effects | 8 instances: `core.color.correct` + `core.stylize.vignette` on each clip |
| Measurement | 2 warm-up frames, then 20 sequential frames (`PreviewEngine::frame`), wall clock |
| **Full quality** | **29.92 fps · 33.42 ms/frame** |
| **Half quality (scrub)** | **87.84 fps · 11.38 ms/frame** |

**Target check:** the Phase C exit criterion is 1080p ≥ 30 fps with 4 tracks and 8 effects. Full
quality measured **29.92 fps — 0.3 % below the target**, i.e. at the target within run-to-run noise
but nominally short; half quality is ~2.9× the target. Recorded as a gap to close (do not treat this
as passing): the likely wins are the GPU composited-frame cache (§3), avoiding the CPU readback +
texture upload in the viewer, and GPU YUV upload (docs/03 §10). The benchmark does not block this
slice and must be re-run on any change to the compositor or the viewer path.

## 3. GPU composited-frame cache: what landed and what remains

Landed (minimal): a `PreviewTransport` LRU of **composited frames** keyed by `(frame, full quality)`,
8 entries. It removes re-composition when the playhead returns to a recent frame (scrub back),
which is the dominant interactive cost after the scheduler settles.

Not landed: the [docs/03 §3](../03-render-engine.md) per-clip GPU texture cache
(`H(clip_id, source_frame_index, effect_chain_hash, resolved_param_hash)`, 2 GB budget, automatic
invalidation per node). That needs `arc-render` to keep per-item render targets and expose them, which
is a compositor change outside this slice. It is the main candidate for closing the 0.3 % full-quality
gap and is scheduled as the next compositor step (C3b), before or with C4.

## 5. Evidence that the viewer runs

`arcline --project <tmp>/smoke.arcline` (a 640×360, 2 s project) was launched with the pinned FFmpeg
DLLs on `PATH`: the process stayed alive for 8 s (window + event loop) and was then stopped; there
was no panic output. Without the FFmpeg `bin/` on `PATH` the app exits with `0xC0000135`
(`STATUS_DLL_NOT_FOUND`), the same requirement as the CLI — `scripts/dev-env.sh` sets it.

## 6. Limits and follow-ups

- **Read-only project snapshot.** The editor loads the saved container; edits and undo land with the
  timeline canvas (C4) through `EngineHost`'s command/event path. No command surface was added here.
- **Texture upload path.** The viewer uses `egui::Context::load_texture` (CPU RGBA → egui-wgpu) while
  the preview engine owns its own headless device. A shared-device zero-copy path
  (`egui_wgpu::RenderState` → `Renderer::with_device` + `register_native_texture`) is the obvious
  next optimization and would remove one full-frame upload per displayed frame.
- **GPU composited-frame cache** per docs/03 §3 is not implemented (§3).
- **No media bin, inspector, timeline canvas or IME** yet (C4/C5).
- **Viewer smoke test is manual** (process liveness); an automated UI test would need a headless
  egui harness, which the project does not have yet.
